# Xiaomi Camera Firmware — живой индекс прошивок

Статический сайт (GitHub Pages), который **в реальном времени ищет прошивки камер Xiaomi / Chuangmi прямо по CDN Xiaomi**. Никакого бэкенда и запечённых списков: браузер сам запрашивает листинг бакета `chuangmi-cdn` и показывает актуальные recovery-пакеты `.zip/.rar`.

**🔎 Сайт:** https://vladikshkwok.github.io/xiaomi-camera-firmware/

## Возможности

- Поиск по **IPC-коду** (напечатан на дне камеры), **названию модели** и **версии/билду**.
- Прямые ссылки на скачивание с CDN, размеры файлов, все доступные версии по каждой модели.
- Данные всегда свежие — тянутся с CDN при каждой загрузке страницы (кнопка «↻ CDN» — перезагрузить).

## Как это работает

CDN-хост скачивания режет query-параметры, но у Xiaomi FDS есть «сырой» эндпоинт с листингом объектов, и **CORS на нём открыт** (`Access-Control-Allow-Origin: *`), поэтому запрос можно делать прямо из браузера:

```
GET https://cnbj2.fds.api.xiaomi.com/chuangmi-cdn?prefix=product/&maxKeys=1000&marker=<nextMarker>
```

Постранично (через `nextMarker`) собираются все объекты под `product/`, фильтруются `.zip/.rar`, группируются по папке-модели (IPC-код), парсится версия/билд/размер. Скачивание идёт с:

```
https://cdn.cnbj2.fds.api.mi-img.com/chuangmi-cdn/<путь объекта>
```

## Как прошивать (卡刷 / recovery)

1. microSD → отформатировать в **FAT32** (карты >32 ГБ — сторонней утилитой).
2. Распаковать `.zip`, скопировать **`tf_recovery.img`** в **корень** карты.
3. Отключить питание камеры, вставить карту, подать питание.
4. Зажать **Reset ~3 сек** до **жёлтого мигания** и голосового «ожидание подключения».
5. Ждать перезагрузки, **не отключая питание** и не вынимая карту. После успеха — вынуть карту.

⚠️ Ставьте только «свой» аппаратный вариант — IPC-код файла должен совпадать с кодом на дне камеры (например `IPC079AE2` vs `IPC079AC1`).

## Названия моделей

Сопоставление «IPC-код → маркетинговое имя» лежит в [`models.json`](models.json). Проставлены только подтверждённые; дополняйте через Pull Request. Для непроставленных ориентир — сам IPC-код.

## Резервный снимок (fallback)

Если живой запрос к CDN из браузера не прошёл, сайт подхватывает [`snapshot.json`](snapshot.json) — снимок листинга — и показывает данные из него с пометкой «резервный снимок от …».

Снимок обновляет GitHub Action [`.github/workflows/snapshot.yml`](.github/workflows/snapshot.yml) (ежедневно + вручную). **Важно:** листинг отдаёт только хост `cnbj2.fds.api.xiaomi.com` (Китай), и раннеры GitHub до него могут не достучаться (таймаут). Поэтому автообновление — best-effort: при недоступности Action не падает, а оставляет прежний снимок. Надёжно пересобрать снимок можно локально (из сети, где хост доступен):

```bash
python3 scripts/snapshot.py   # перезапишет snapshot.json
```

Живой поиск при этом работает у пользователей всегда, пока их браузер достаёт до CDN.

## Дисклеймер

Все прошивки — официальные, размещены Xiaomi на её собственном CDN. Проект лишь индексирует публично доступные объекты и не хостит файлы. Даты объектов в хранилище — метка пересинхронизации, а не дата релиза; ориентируйтесь на номер версии/билда.
